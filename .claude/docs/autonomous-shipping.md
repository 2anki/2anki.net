# Autonomous shipping

Agents merge and deploy their own PRs through `/ship`, hard-rail PRs included. Alexander reviews the merged-PR list. Decided 2026-08-26 (PR #4244); rail PRs became agent-merged on 2026-10-05. This doc is the reference the rules point at.

## Why it is safe to let agents merge

Before this, every merge was a human step — but branch protection on `main` required zero checks and zero reviews, and every real gate lived in a local Claude hook. The human step was a convention, not a mechanism. Now the gate is mechanical and lives in two places:

- **GitHub** — required status checks on `main`: `static (22.20.0)`, `test (22.20.0)`, `build (22.20.0)`, `test-web (22.20.0)`, `playwright (22.20.0)`, with `strict: true` (branch must be up to date). Every workflow runs on every push so a required check is never left pending by a path filter. Applies to Alexander's merges too (`enforce_admins`).
- **The `check-merge-status.py` hook** on every `gh pr merge` from a Claude session — see the gate table.

## The merge gate

| # | Condition | How it is checked |
| --- | --- | --- |
| 2 | Every rollup entry COMPLETED and non-FAILURE; every `test*` check RAN; dep changes have a SUCCESS test | `gh pr view --json statusCheckRollup`; changed files from the paginated REST list all four merge hooks share (`merge_command.changed_files`), `gh pr view`'s first 100 when that call fails |
| 3 | Review-agent pass marker for the head SHA | `<!-- ship-review: pass sha=<headRefOid> -->` in a PR review or comment; dependabot exempt. **Honor-system**, like the browser attestation: anyone who can comment can post it — it binds the operator's session to having run the review, it does not prove the review ran |
| 5 | Browser attestation (web/src diffs) and changelog (feat/fix) | existing hooks |
| 6 | PR came from a spec (`<type>/spec-<slug>` branch + a spec-lifecycle commit) → body carries `## Deviations from spec` | `gh pr view --json headRefName,body,commits`; non-spec PRs unaffected |
| 7 | `feat:`/`fix:`/`perf:`/`refactor:` PR (title or any commit headline) changing a file under `src/` or `web/src/` other than tests (`.test.`, `.spec.`, `__tests__/`, `__snapshots__/`, `fixtures/`, `__fixtures__/`, `_mock/`, `setupTests.`, `src/test/`, `web/src/test/`), changelog JSON and `.md` docs → body carries a non-empty `## Who else this reaches` section | `gh pr view --json title,commits,files,body`; empty = only whitespace, HTML comments, bullet marks, a header-only table, or lines and rows of only TBD/TODO/N/A/None/-/... or empty cells; reverts are exempt. The hook checks presence; the `/ship` step 2 reach reviewer, which runs on every such PR whatever its paths, checks that each reachable population has a test and each unreachable one a reason. Added after #4589 dropped a notice for signed-in free users while claiming "byte-for-byte unchanged" (#4789) and #4730 broke prerendered landing pages (#4901) |

All four merge hooks accept only the exact command `/ship` runs, `gh pr merge <n> --repo 2anki/server --squash` (or `--repo 2anki/2anki.net`), alone in the Bash call; a trailing ` 2>&1` is the only suffix allowed. Detection fails closed: any Bash command containing both `gh` (or `github`) and `merge`, anywhere and in any case, counts as a merge attempt and is denied unless it is that exact form, so reads that only name a merge field (`--json mergeStateStatus`, `--state merged`) and `git commit -m` messages naming both words are denied too; write those messages with `git commit -F <file>`. They also deny when `gh pr view` fails, answers with another repo's PR or another PR, or the gate itself errors. Words built at run time fail closed as well: a command with `merge`, `gh` or `github` and any `$` or backtick, or with any ANSI-C quote `$'`, counts as a merge attempt, so `gh` commands that use a variable or `$( )` are denied (use `--body-file` and literal values). The hooks guard against an accidental or unreviewed merge, not a determined adversary with a shell and a token; the exact-form allowlist is the control and obfuscation detection is best effort. A merge run from a script file, another language or a gh alias defined earlier is not seen; that is a policy violation, as `CLAUDE_SKIP_SAFETY` is. Until #5193 a `gh pr view` error failed open and the hooks parsed any merge form, which let the PR the gate read differ from the PR that merged. A human merges from the GitHub UI, where the hooks do not run. SonarCloud was a fifth condition until 2026-10-01; it was removed because it added a serial wait that timed out on 8% of PRs while `main` carried 1,102 unactioned findings, the gate rating only new code.

The only bypasses are ones an agent cannot reach from inside a session: merging from the GitHub UI, or launching the session with the env var set (`CLAUDE_SKIP_SAFETY=1 claude`). A `CLAUDE_SKIP_SAFETY=1` prefix typed into a command is deliberately ignored — a PreToolUse hook runs before the shell, and honoring the prefix would let any agent self-bypass the gate (caught by the commit security review on #4244).

## Hard rails

`.claude/hooks/hard_rails.py` lists the high-blast-radius surfaces: auth, payments/Stripe, subscriptions, checkout, passes, webhooks, quota constants, migrations and the generated data layer, `src/server.ts`, `.github/`, the harness (`.claude/`, `CLAUDE.md`) and the prod safety limits. It no longer blocks a merge. `/ship` uses it to classify the PR and, on a hit, runs the matching extra verification before and after the merge (`.claude/commands/ship.md`, step 1b and step 6b). A rail PR merges on that evidence; it does not wait for Alexander, unless its body records an unverified assumption (`ship.md` step 1).

## `/ship` in one paragraph

Preflight (draft? rail class? rebased?) → rail verification when the classifier hits → review agent (fresh read-only reviewers run by `/ship` step 2; fix rounds until clean, no cap) posts the marker → wait for the rollup → `gh pr merge <n> --repo 2anki/server --squash` merges directly (hooks re-verify first; it is the only merge form they accept) → confirm the PR state is `MERGED` and read the squash commit's SHA with `git log --grep` (a refused merge means a required check went red or `main` moved; fix or rebase on the branch and go again) → find the deploy run for the merge SHA and watch it → `curl /api/version` must report the merge SHA, then `/deploy-status` → on failure, `git revert` on a `revert/<slug>` branch shipped through the same command (review agent skipped for a mechanical revert), comment on the deploy-failure issue. Full steps: `.claude/commands/ship.md`.

Only these halt, the list in `CLAUDE.md` Process. A secret exposure halts the whole run; the value and spend halts, and the rail-assumption case under the destructive bullet, hold their own PR (draft, named in the summary) while the run continues with other items; any other destructive step is not executed and the run continues:

- A value only he holds: a prod secret, a Google or Stripe dashboard login, a payment card, or whether to take a third-party bump that fails, has an open finding after `/security-review`, or is held in `.claude/rules/dependencies.md`, pinned under `pnpm.overrides` in `package.json`, or on the security-surface or install-time-build list in the dependabot worker (the fix lives upstream, not on the branch).
- Incurring new spend (a new paid service, plan, model, or paid batch run) needs his approval.
- A destructive, irreversible action. An unverified assumption on a rail path (auth, payments, migrations) counts, because a wrong guess there is not undone by a revert.
- A confirmed secret exposure or auth bypass found mid-run: halt and tell him.

Everything else is fixed on the branch and the run goes on. For a value only he holds, an unattended run ships behind a safe default if one exists, otherwise leaves the PR draft and names the value in the morning summary (a price, payment or Stripe value, a payment card, or a third-party bump decision never ships behind a default, it stays draft and is named in the summary); spend and destructive halts never ship behind a default (spend leaves a draft, a destructive step is not executed, both are named in the summary), and an auth, JWT, webhook or signing secret never gets a default (a missing one fails closed at boot and the PR stays draft with the variable named); the only other draft is a failure the branch cannot change (a runner outage, a GitHub incident, per `/ship` step 4), held on a wakeup until green while the run continues with other items; a red unrelated to the diff (a timeout, a cancelled or crashed runner, a step that died before any test ran) gets the one rerun `/ship` step 4 allows, and any other red is fixed on the branch.

Sanctioned exemptions inside `/ship` only: starting `pnpm dev` for the browser attestation (kill it after), and the read-only `/deploy-status` SSH.

## Decisions and manual steps

Trio decisions land in the PR body under `## Decisions` (the `## Decisions made overnight` heading in `/overnight-prs`, `## Decisions` elsewhere). The merged PR is where Alexander overrides a call — comment on it or open a follow-up. A step only Alexander can do (a prod secret other than an auth, JWT, webhook or signing secret, which fails closed and stays draft; a free-tier third-party account) ships behind a safe default, and in an interactive run the agent asks him for it in the session chat and keeps shipping behind the default until he answers (an unattended run names it in the morning summary; a price, payment or Stripe value never ships behind a default, it stays draft and is named there too). Do not open `Needs you` issues; they were dropped on 2026-10-05 because they piled up as issues to close, and three more were still open on 2026-10-27. Record the step as a draft item with Owner `Alexander` in the private Follow-ups project instead (`.claude/docs/follow-ups-project.md`). The daily `Shipped <date>` digest issues (label `shipped-digest`, 2026-08-26 to 2026-09-08) were dropped: they duplicated `gh pr list --state merged` and cost an issue a day to close. Agents never create one.

## Throughput

Docs-only pushes (`.claude/**`, `Documentation/**`, `*.md` outside `src/` and `web/` — oxfmt formats Markdown under both, so those stay code) still run every required job, but each job asks `.github/actions/changes` first and finishes in seconds when nothing needs building — a `paths-ignore` would leave the required checks unreported and the PR blocked forever. `strict: true` means a PR behind `main` must rebase and re-run CI before it can merge; two concurrent `/ship` runs serialize at roughly ten minutes per PR. Dependabot PRs behind `main` need `@dependabot rebase`. The merge queue ran from 2026-09-10 to 2026-10-15 and was then disabled: it re-ran the workflows that had just passed on the head SHA, about seven minutes per PR, and `/ship` already rebases and waits for green. `gh pr merge` merges directly again; `/ship` step 4 describes the refused-merge handling.

## Rolling it out / rolling it back

- Branch protection was applied 2026-08-26 with `gh api -X PUT repos/2anki/2anki.net/branches/main/protection` — use the canonical repo name for writes, `gh api` does not follow the rename redirect (`2anki/server` answers a PUT with HTTP 307). To read the current state: `gh api repos/2anki/server/branches/main/protection`.
- To pause autonomous merging without touching code, set `required_approving_review_count` to 1 in branch protection — every merge then waits for a human approval. Restore with the same PUT.
